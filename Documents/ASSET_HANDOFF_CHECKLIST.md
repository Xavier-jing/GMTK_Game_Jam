# 资产交付与合规验收清单

## 1. 使用方式

每批准备进入游戏的图像、模型、字体、动画、音乐、音效、配音或视频，都必须由人类负责人完成本清单。

可将“单项资产记录”复制到 Issue、Pull Request 或团队交付记录中。同一来源、同一许可证、同一导入规则的系列资产可以合并记录，但必须列出全部文件。

任何“未知”“待确认”或无法证明未使用生成式 AI 的资产都不得进入比赛提交版本。

## 3. 批次交付检查

### 合规

- [ ] 每个资产都能追溯到明确的人类作者或允许的第三方来源。
- [ ] 每个第三方资产都有可保存的许可证证明。
- [ ] 全部资产均完成无 AI 生成和无 AI 修改声明。
- [ ] 需要署名的内容已加入比赛页面或游戏 Credits。
- [ ] 没有把临时占位、网络截图或来源未知文件混入正式目录。

### 文件与导入

- [ ] 命名、目录和格式符合 [`ART_ASSET_SPEC.md`](./ART_ASSET_SPEC.md)。
- [ ] 图像的 PPU、Pivot、Slice、Filter Mode 和压缩设置已检查。
- [ ] UI 九宫格、锚点和不同宽高比已检查。
- [ ] 动画帧率、循环、Pivot 和 Animator 参数已检查。
- [ ] 音频响度、循环点、Load Type、压缩和 Mixer Group 已检查。
- [ ] 每个新增或移动资产都有正确的 `.meta`，且由人类操作 Unity 生成或保留。

### 代码与场景挂接

- [ ] 需要的 C# Inspector 字段已经由程序提供。
- [ ] 资产引用由人类在 Unity Editor 中完成。
- [ ] 没有让智能体保存 Scene、Prefab、Material、Animation、Mixer 或 Import Settings。
- [ ] 没有重复 `ScreenId`、LoadingScreen、UIService 或 EventSystem。
- [ ] 场景切换、暂停、设置、BGM/SFX 相关流程完成冒烟测试。

### Git 交付

- [ ] 提交只包含本批次预期的资产、`.meta` 和经授权的代码/文档。
- [ ] 没有误带 `.DS_Store`、个人 IDE 配置、Library、Temp、Logs 或构建产物。
- [ ] 没有覆盖其他成员未合并的场景或 Prefab 修改。
- [ ] Pull Request 或提交信息列出资产来源、挂接位置和验证结果。

## 4. 发现问题时的处理

- 来源或 AI 使用情况不明确：停止接入并移出比赛提交候选范围，等待人类负责人确认。
- `.meta` 丢失或 GUID 变化：不要继续保存引用场景，先由人类从 Git 或原作者恢复正确 `.meta`。
- 场景/Prefab 冲突：保留双方版本，交由熟悉该场景的人类成员在 Unity 中合并。
- 需要新增程序接口：使用 [`UNITY_CONTENT_INTEGRATION_GUIDE.md`](./UNITY_CONTENT_INTEGRATION_GUIDE.md) 中的“程序挂接申请模板”。
- 运行结果与规格不一致：先记录重现步骤，不让智能体通过修改艺术资产“自动修复”。
